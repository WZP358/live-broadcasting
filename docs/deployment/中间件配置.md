# 中间件配置

本文档说明本项目本地运行前需要准备的中间件：MySQL、Redis、MinIO、内网穿透。

## 1. MySQL

用途：业务数据存储。

推荐配置：

| 项目 | 值 |
| --- | --- |
| Host | `localhost` |
| Port | `3306` |
| Database | `ant-live` |
| 用户名 | 与 `backend/src/main/resources/application.yml` 的 `spring.datasource.username` 保持一致 |
| 密码 | 与 `backend/src/main/resources/application.yml` 的 `spring.datasource.password` 保持一致 |
| 字符集 | `utf8mb4` |

创建数据库：

```sql
CREATE DATABASE IF NOT EXISTS `ant-live`
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_general_ci;
```

执行根目录 SQL 文件：

```bat
mysql -uroot -p ant-live < ant-live.sql
```

说明：

- 初始化 SQL 使用项目根目录的 `ant-live.sql`。
- `backend/src/main/resources/sql/ant-live.sql` 是后端资源目录里的副本，文档和初始化流程以根目录 SQL 为准。

后端连接配置位置：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/ant-live?characterEncoding=utf-8&serverTimezone=GMT%2b8
```

## 2. Redis

用途：缓存、在线状态、验证码、限流、直播间观众状态等。

推荐配置：

| 项目 | 值 |
| --- | --- |
| Host | `localhost` |
| Port | `6379` |
| Database | `0` |
| Password | 本地为空，按 `application-local.yml` 覆盖 |

启动 Redis：

```bat
redis-server
```

检查 Redis：

```bat
redis-cli -h 127.0.0.1 -p 6379 ping
```

返回 `PONG` 即正常。

注意：`3306` 是 MySQL 端口，Redis 端口是 `6379`。

后端连接配置位置：

```yaml
spring:
  redis:
    host: localhost
    port: 6379
    database: 0
    password:
```

## 3. MinIO

用途：图片、封面、上传文件等对象存储。

推荐配置：

| 项目 | 值 |
| --- | --- |
| API 地址 | `http://localhost:9000` |
| Console 地址 | `http://localhost:9001` |
| Access Key | `minioadmin` |
| Secret Key | `minioadmin` |
| Bucket | `live.file.bucket` |
| Bucket 权限 | Public，只读公开访问 |

启动 MinIO 示例：

```bat
minio server D:\minio\data --address ":9000" --console-address ":9001"
```

创建桶并设置公开读取权限。

下面这些 `mc` 命令需要在 MinIO Client 的 `mc.exe` 所在目录执行，或者先把 `mc.exe` 所在目录加入系统 `PATH`：

```bat
mc alias set local http://127.0.0.1:9000 minioadmin minioadmin
mc mb --ignore-existing local/live.file.bucket
mc anonymous set download local/live.file.bucket
```

如果本地 `mc` 版本较旧，公开权限命令可以改用：

```bat
mc policy set public local/live.file.bucket
```

后端启动时也会根据配置自动创建 `live.file.bucket`，并设置公开读策略；但为了避免启动时连接失败，建议先启动 MinIO，再启动后端。

后端连接配置位置：

```yaml
minio:
  endpoint: http://localhost:9000
  ip: localhost
  port: 9000
  accessKey: minioadmin
  secretKey: minioadmin
  bucketName: live.file.bucket

dromara:
  x-file-storage:
    minio:
      - platform: minio-1
        enable-storage: true
        access-key: minioadmin
        secret-key: minioadmin
        end-point: http://localhost:9000
        bucket-name: live.file.bucket
        domain: http://localhost:9000/live.file.bucket/
```

## 4. 内网穿透

用途：支付宝沙箱支付后，需要能访问本地项目地址。这里要分清楚前端回跳地址和后端通知地址。

本项目涉及三类地址：

| 配置项 | 应该指向 | 用途 |
| --- | --- | --- |
| `alipay.returnUrl` | 前端地址，例如 `http://localhost:5174/#/center/dollar/wallet` | 用户支付完成后，浏览器最终回到钱包页 |
| `alipay.notifyUrl` | 后端公网地址，例如 `/api/v1/wallet/alipay/notify` | 支付宝服务器异步通知后端入账 |
| `alipay.syncReturnUrl` | 后端公网地址，例如 `/api/v1/wallet/alipay/return` | 支付宝同步返回后端，后端处理后再跳回 `returnUrl` |

如果你说的“内网穿透是前端”，通常对应的是 `returnUrl`：把前端 `5174` 暴露出去，让支付完成后浏览器能回到前端页面。

但 `notifyUrl` 必须能被支付宝服务器访问到后端接口，否则异步通知不会进后端，充值入账可能不稳定。当前代码里同步返回接口也在后端：

```text
POST /api/v1/wallet/alipay/notify
GET  /api/v1/wallet/alipay/return
```

推荐配置方式：

| 场景 | 配置 |
| --- | --- |
| 只配置一个穿透地址 | 优先穿透后端 `127.0.0.1:8088`，`syncReturnUrl` 走后端，再由后端跳回前端 `returnUrl` |
| 前端也需要公网回跳 | 额外穿透前端 `127.0.0.1:5174`，把 `returnUrl` 改成前端公网地址 |
| 只有前端穿透 | 可以用于页面回跳，但还需要后端公网地址或反向代理转发 `/api/v1/wallet/alipay/*` 到后端 |

NATAPP 示例：

```bat
natapp -authtoken YOUR_BACKEND_TOKEN
```

后端隧道本地地址配置为：

```text
127.0.0.1:8088
```

前端隧道本地地址配置为：

```text
127.0.0.1:5174
```

拿到公网地址后，更新后端支付宝配置：

```yaml
alipay:
  notifyUrl: "http://后端公网域名/api/v1/wallet/alipay/notify"
  syncReturnUrl: "http://后端公网域名/api/v1/wallet/alipay/return"
  returnUrl: "http://前端公网域名/#/center/dollar/wallet"
```

当前项目示例里使用过 NATAPP 免费域名：

```yaml
alipay:
  notifyUrl: "http://qbb9ec9c.natappfree.cc/api/v1/wallet/alipay/notify"
  syncReturnUrl: "http://qbb9ec9c.natappfree.cc/api/v1/wallet/alipay/return"
  returnUrl: "http://localhost:5174/#/center/dollar/wallet"
```

免费穿透域名可能会变化，每次重启穿透工具后都要确认域名是否改变，并同步修改 `application.yml`。

## 启动顺序

建议按下面顺序启动：

1. MySQL：创建 `ant-live` 数据库，并执行根目录 `ant-live.sql`
2. Redis：启动 `6379`
3. MinIO：启动 `9000`，创建 `live.file.bucket`，设置 public
4. 内网穿透：按支付宝配置需要，映射后端 `8088` 和前端 `5174`
5. 后端：启动 Spring Boot `8088`
6. 前端、直播服务器、模型服务按 `README.md` 的项目启动顺序启动

## 快速检查

```bat
mysql -uroot -p -e "SHOW DATABASES LIKE 'ant-live';"
redis-cli -h 127.0.0.1 -p 6379 ping
curl http://127.0.0.1:9000/minio/health/live
curl http://127.0.0.1:8088/
```

`curl http://127.0.0.1:8088/` 不一定有页面返回，只要后端进程正常、接口能访问即可。
