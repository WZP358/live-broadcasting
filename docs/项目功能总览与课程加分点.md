# PulseLive 项目功能总览与课程加分点

## 1. 项目简介

PulseLive 是一个直播平台课程项目，覆盖用户端观看、主播端开播、管理员审核和 AI 辅助能力，形成了从“看直播、开直播、管直播”到“审核、客服、数据、消息”的完整闭环。

## 2. 功能总览

### 2.1 用户端

- 首页推荐和分区浏览
- 搜索主播、房间标题、分区
- 直播间观看、弹幕互动、礼物发送
- 关注主播、查看观看历史
- 系统消息通知
- 钱包、充值、账单查看
- 举报直播间内容
- 联系客服并提交工单

### 2.2 主播端

- 个人中心与资料编辑
- 开播准备页
- 网页开播工作台
- 屏幕直播 / 摄像头直播切换
- 直播预览、停止直播
- 实时降噪
- 摄像头浮窗
- 互动助手与直播状态看板
- 直播数据看板
- 守护管理
- 礼物流水与收益数据

### 2.3 管理端

- 用户管理
- 直播间管理
- 内容审核
- 举报处理
- 客服工单处理
- 礼物管理
- 分类管理
- 菜单管理
- 角色管理
- 字典管理
- 系统配置
- 系统消息
- 账单管理
- 数据总览

### 2.4 AI 与实时能力

- 小脉 AI 助手
- 弹幕氛围 AI 分析
- 直播内容风险识别
- 实时音频降噪
- 直播推荐
- WebSocket 实时互动
- WebRTC 网页开播链路
- 上下文感知 AI 辅助

## 3. 课程作业加分点

| 加分点 | 体现方式 | 为什么加分 |
|---|---|---|
| AI 智能体接入 | `小脉 AI 助手`、弹幕氛围分析、当前页面上下文感知 | 不只是“接了一个聊天框”，而是能结合用户所在页面给操作建议 |
| 实时开播能力 | 网页端直接开播、屏幕/摄像头切换、预览、停止 | 体现 WebRTC 和实时媒体链路，不是静态展示页 |
| 实时降噪 | 主播开播时可启用降噪 | 有实际业务价值，能体现音频处理能力 |
| 内容安全 | 直播风险检测、举报、管理员处理 | 有完整治理闭环，不只是能播不能管 |
| 直播运营闭环 | 关注、历史、礼物、钱包、账单、守护、数据看板 | 业务链条完整，符合“平台型项目”要求 |
| 后台管理体系 | 用户、房间、分类、礼物、角色、配置、消息管理 | 体现前台 + 后台的一体化设计 |
| 实时通信 | 弹幕、通知、开播信令 | 说明项目不是纯页面拼装，而是有实时交互能力 |
| 主题化 UI | 统一的个人中心、直播间、管理后台风格 | 展示项目完成度和商业化感，更适合答辩展示 |
| 后台演示模式 | 管理员控制台一键开启/关闭多直播间录播数据 | 降低答辩现场风险，同时体现后台运营控制能力 |

## 4. 答辩建议重点讲的 4 个点

1. AI 智能体不是摆设，而是嵌入页面操作建议、弹幕氛围分析和平台治理场景。
2. 开播链路是完整的，包含预览、推流、切换模式、停止、实时状态。
3. 平台有内容安全和人工处理机制，不是单纯“播出去就完了”。
4. 用户、主播、管理员三类角色都能找到对应功能，项目闭环完整。

## 5. 演示脚本

```powershell
# 启动前端、后端和小脉 AI Agent
.\scripts\start-demo.ps1

# 停止演示进程
.\scripts\stop-demo.ps1
```

启动服务后，登录管理员账号进入 `系统后台 -> 控制台`，打开“演示模式”开关即可启动多间录播直播间；关闭开关后只会下线演示房间，不影响真实主播。演示房间使用本地视频素材，适合展示首页在线直播、分类、搜索、进入直播间、礼物和聊天室。

| 账号 | 密码 | 用途 |
|---|---|---|
| `demo_viewer_01` | `123123` | 观众端完整流程 |
| `demo_anchor_01` | `123123` | 主播中心、开播工作台和礼物流水 |
| `demo_admin` | `123123` | 管理后台、演示模式、审核与客服处理 |

演示录播素材位于 `frontend/public/demo-videos/`，封面位于 `frontend/public/demo-covers/`。答辩结束后如需释放空间，可以删除这两个目录；数据库中的演示直播间带有 `PULSELIVE_DEMO_ROOM` 标记，平时通过后台开关关闭即可。
